## 自测报告

合入前的自测结论，报告与预览以附件形式随 MR 上传，**不入库**。

### 结论

15 个场景，累计 **错误 0 项、告警 0 项**；可判定的顶层分区合并覆盖 **16/16（100%）**。

### 场景矩阵

| 场景 | 验证点 | 错误 | 告警 |
|------|--------|------|------|
| 基线-完整数据 | 所有分区都应显示，不应有任何错误 | 0 | 0 |
| 仅税 | 汇总行文案为 Tax，弹层只列税项 | 0 | 0 |
| 仅费 | 汇总行文案为 Fees，弹层只列费用项 | 0 | 0 |
| 无税无费 | 不渲染 i 图标，不渲染弹层与弹层 JS | 0 | 0 |
| 无顾客信息 | 顾客分区整块不渲染，分隔线不重复 | 0 | 0 |
| 无支付信息 | Payment 整块不渲染（含标题与分隔线） | 0 | 0 |
| 无门店 Logo | 不出图片，按配置决定是否走占位图标 | 0 | 0 |
| OO 取餐码胶囊 | 胶囊显示「类型 / 取餐码」，不显示桌台 | 0 | 0 |
| 堂食有桌台 | 胶囊只显示 Dine In，不拼接桌台号 | 0 | 0 |

自测覆盖三类运行时故障：空值风险（`${}` 取不到值又没写 `!默认值`，会抛 `InvalidReferenceException`）、
数组越界（`content[n]` 超出实际长度）、指令闭合（`<#if>` / `<#list>` 未配对）。

### 请评审重点确认（自测覆盖不到的部分）

自测是静态推演，不启动 FreeMarker 引擎，以下几项**没有被验证过**，不要因为上面全绿就认为已验收：

1. **两个依赖自定义函数的分支判不了真假**，需人工或真机确认：
   - 第 301 行 `orderBadgeText?has_content`（单号 / 类型胶囊）
   - 第 317 行 `serverLabelText?has_content`（同上）
2. **视觉样式**：断行、对齐、长文案溢出、税费弹层位置 —— 见预览附件
3. **邮件客户端兼容性**：Outlook 走 Word 引擎、Gmail 会剥离 `<style>`
4. **短信通道与短链跳转**
5. **业务口径**：金额分区的税费合并展示逻辑是否符合产品预期
